# E&U 店舗システム（プロトタイプ）

クレープ＆うま茶の店舗向けに、自社開発を前提として作った試作です。
**データはすべてダミー**で、実在の売上・スタッフ・取引先ではありません。

👉 https://kento-umapro.github.io/enu-system/

合言葉が必要です（関係者にのみ共有）。

## 作ってあるもの（全14画面）

| セクション | 画面 |
|---|---|
| レジ | 注文入力 / 注文履歴 / レジ締め |
| 売上 | 日報 / 経営ダッシュボード / 商品分析（ABC分析） |
| シフト | シフト募集 / 希望集計 / シフト作成 |
| 勤怠 | 勤怠一覧 / 人件費集計 / 締め処理 |
| マスタ | 商品・レシピ / 原材料・発注 |

## 全部が1本につながっています

```
レジで会計
  → 3枚印字（クレープ伝票 / カップラベル / 番号レシート）
  → 注文履歴
  → 日報の売上・原価率（レシピから自動計算）
  → 経営ダッシュボード（FL率・目標達成率）
  → 原材料の理論消費
  → 発注リスト（発注先別：インフォマート / LINE / FAX / 電話）
```

## シフトは募集から締めまで1サイクル

① 募集 → ② 希望提出 → ③ 集計 → ④ シフト作成 → ⑤ 確定・通知 → ⑥ 実績突合 → ⑦ 締め・給与

必要人数は「売上予測 ÷ 人時売上高の目標 ÷ 1人あたりの実働時間」で自動算出し、
シフトを組んだ時点で人件費率の見込みが出ます。

## 試してみるところ

1. **レジで何品か打って会計** → 日報・商品別・原材料の数字が動きます
2. **シフト作成で「希望から叩き台を作る」** → 15日分が自動で埋まります
3. **マスタの商品行をクリック** → レシピの内訳と原価が出ます

## 構成

- `index.html` … 合言葉の入力画面。正しい合言葉でのみ本体を復号して起動します
- `app.enc` … 本体（AES-256-GCM で暗号化。鍵は合言葉から PBKDF2 で導出）

静的サイトの合言葉は、URL を知っている人を一段止めるためのものです。
強度は合言葉の長さに依存します。公開情報としての機密は含めていません。

仮メニュー：クレープ10種／うま茶10種／物販3種、トッピング各10種、原材料18種。
注文データはブラウザのローカル保存で、端末をまたいで共有されません。
